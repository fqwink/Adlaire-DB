# Adlaire DB プロジェクト憲章

## 位置づけ

プロジェクト憲章は仕様ではない。

プロジェクト憲章は、Adlaire DB が何を目指すか、なぜ作るか、何を優先するかを示す文書である。実装者は本憲章を背景情報として参照できるが、本憲章だけを根拠に実装、テスト、完了判定をしてはならない。

## 目的

Adlaire DB は、Turso Cloud 互換の自己ホスト DB 管理基盤を目指す。

SQLite / libSQL 系の軽量さを保ちながら、Turso Cloud と同等の管理体験、API、SDK 接続、認証、metadata、organization / group / location / quota、backup、restore、PITR、branch、replication、metrics、HA、運用証跡を自己ホスト環境へ持ち込むことを目的とする。

## 価値

- Turso Cloud 互換の管理体験を自己ホスト環境で利用できること
- libSQL SDK 互換により、既存クライアントの移行負荷を小さくすること
- 単なる SQLite wrapper ではなく、DB 管理基盤として運用できること
- 将来的に、外部契約を保ったまま内部実装を段階的に内製化できること

## 優先順位

実装判断で迷う場合の価値判断は、以下を優先する。

1. Turso Cloud 互換
2. libSQL SDK 互換
3. 既存 Adlaire 後方互換
4. 自己ホスト運用性
5. 内製化しやすさ
6. Adlaire 独自拡張

この優先順位は方針であり、仕様ではない。実装に使う場合は、必ず `docs/spec/index.md` 以下の仕様へ落とし込む。

## 実装との関係

- プロジェクト憲章は実装対象ではない
- プロジェクト憲章は仕様正本ではない
- プロジェクト憲章と仕様が矛盾した場合は、仕様を優先する
- プロジェクト憲章を実装へ反映する場合は、先に仕様変更 PR を作成する
